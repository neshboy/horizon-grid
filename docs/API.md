# API Reference

> **Superseded.** This page predates [API_DOCUMENTATION.md](API_DOCUMENTATION.md), which covers
> every route (including analysis, hunting, pivot, basket, and case management, none of which are
> documented below) and is now the canonical API reference — kept here for history only.

REST + SSE reference for the HORIZON GRID backend
(`backend/app/api/routes/`). Full OpenAPI docs (all request/response
schemas, auth requirements per route) are auto-generated by FastAPI at
**`http://localhost:8000/docs`** (and the raw schema at
`/api/v1/openapi.json`). This document exists specifically to describe the
**SSE event contract** of `POST /api/v1/lookup/stream`, which OpenAPI has no
good way to express — everything else here is a quick-reference summary; the
generated docs are authoritative for exact schemas.

All routes are mounted under the `/api/v1` prefix (`settings.api_v1_prefix`).
All routes except `/auth/register` and `/auth/login` require
`Authorization: Bearer <access_token>`.

## Auth

Base path: `/api/v1/auth` (`app/api/routes/auth.py`).

### `POST /api/v1/auth/register`

Create a user account. **No auth required.**

Request body:
```json
{ "email": "you@example.com", "password": "...", "full_name": "Your Name" }
```

Response `201`:
```json
{ "id": "<uuid>", "email": "you@example.com", "full_name": "Your Name", "role": "admin" }
```

The **first** user ever registered gets `role: "admin"`. Every registration
attempt after that is rejected with `403 Forbidden` ("Self-registration is
closed. Ask an administrator to create your account from the Administration
page.") rather than defaulting to a lesser role. `400` if the email is
already registered.

### `POST /api/v1/auth/login`

Exchange credentials for a token pair. **No auth required.**

Request body:
```json
{ "email": "you@example.com", "password": "..." }
```

Response `200`:
```json
{ "access_token": "<jwt>", "refresh_token": "<jwt>", "token_type": "bearer" }
```

`401` on invalid credentials, `403` if the account is disabled
(`is_active: false`).

### `POST /api/v1/auth/refresh`

Exchange a refresh token for a new access/refresh pair. Takes
`refresh_token` as a query/body string parameter and returns the same
`TokenResponse` shape as `/login`. `401` if the token is invalid, expired,
or not of type `refresh`.

### `GET /api/v1/auth/me`

Returns the current authenticated user. Requires a valid access token.

```json
{ "id": "<uuid>", "email": "you@example.com", "full_name": "", "role": "analyst" }
```

## Lookup

Base path: `/api/v1/lookup` (`app/api/routes/lookup.py`). Requires
permission `lookup:create` (POST) or `lookup:read` (GET) — see
`ROLE_PERMISSIONS` in `app/models/user.py` (`admin`/`analyst` can create;
all roles including `viewer` can read).

### `POST /api/v1/lookup/stream` — the core SSE endpoint

Runs one full IOC investigation and streams every stage of the pipeline as
Server-Sent Events. This is the endpoint the frontend's search box drives.

**Request**
```json
{ "value": "8.8.8.8", "ioc_type_hint": null }
```
- `value` (string, required) — the raw IOC as entered by the user.
- `ioc_type_hint` (string, optional) — one of the `IOCType` enum values
  (`app/ioc/types.py`, e.g. `"ipv4"`, `"domain"`, `"sha256"`, `"cve"`) to
  override auto-detection. If omitted, the type is inferred by
  `detect_ioc_type()`. `422` if the type cannot be determined and no hint
  was given.

**Response**: `Content-Type: text/event-stream`. Each event is framed as:
```
event: <event_name>
data: <json>

```
(each frame is `event: ...\ndata: ...\n\n`, matching the standard SSE wire
format; `data` is a single JSON-encoded line).

**Event sequence** (see `docs/ARCHITECTURE.md` for the full lifecycle
narrative):

```
detected → provider_result* → provider_summary* → correlation → final_assessment → done
                                                                                  ↘ error (on failure, replaces final_assessment/done)
```

#### `event: detected`

Emitted once, immediately after the IOC type is resolved and the
`IOCLookup` row is created.

```json
{ "lookup_id": "<uuid>", "ioc_value": "8.8.8.8", "ioc_type": "ipv4" }
```

#### `event: provider_result`

Emitted once per provider that supports the detected IOC type, as soon as
that provider finishes (order is completion order, not registration order).
Payload is `ProviderResult.to_dict()` (`app/providers/base.py`):

```json
{
  "provider_id": "virustotal",
  "provider_name": "VirusTotal",
  "category": "threat_intel",
  "status": "ok",
  "ioc_value": "8.8.8.8",
  "ioc_type": "ipv4",
  "data": { "verdict": "clean", "detection_ratio": "0/70", "...": "..." },
  "source_url": "https://www.virustotal.com/gui/search/8.8.8.8",
  "error_message": null,
  "latency_ms": 842,
  "fetched_at": 1735000000.123,
  "from_cache": false
}
```

- `status` is one of: `ok`, `error`, `timeout`, `rate_limited`,
  `not_configured`, `unsupported_ioc`, `no_data`.
- `data` shape varies per provider; see
  `docs/ARCHITECTURE.md#normalized-fields` for the common keys the
  correlation engine and AI service rely on (`verdict`, `reputation`,
  `detection_ratio`, `resolved_ips`, `malware_families`, `threat_actors`,
  `mitre_techniques`, `cves`, etc).
- `error_message` is populated for non-`ok` statuses; `source_url` links to
  the provider's own UI for that indicator when available.

#### `event: provider_summary`

Emitted once for every `provider_result` whose `status` was `"ok"`,
immediately after that provider's AI summary is generated (so it interleaves
with, rather than strictly follows, all `provider_result` events). Payload
is a `ProviderSummary` (`app/ai/schemas.py`):

```json
{
  "provider_id": "virustotal",
  "what_it_knows": "VirusTotal reports 0 of 70 engines flagged this IP as malicious.",
  "reputation": "clean",
  "detection_status": "0/70 engines",
  "threat_level": "none",
  "confidence": "high",
  "interesting_findings": [],
  "relationships": [],
  "unique_observations": [],
  "caveats": null
}
```

#### `event: correlation`

Emitted once, after every provider has reported and every eligible
`provider_summary` has been generated. Payload:

```json
{
  "nodes": [
    { "node_id": "ipv4:8.8.8.8", "ioc_type": "ipv4", "value": "8.8.8.8", "labels": [] }
  ],
  "edges": [
    {
      "source": "ipv4:8.8.8.8",
      "target": "domain:example.com",
      "relationship": "resolves_to",
      "confidence": 0.7,
      "provenance": "virustotal"
    }
  ]
}
```

`provenance` is a comma-joined list of provider IDs if multiple providers
asserted the identical edge. Note: this event's `nodes`/`edges` are **not**
persisted verbatim for later retrieval via `GET /api/v1/lookup/{id}` — that
endpoint returns edges as flat DB rows via a separate mechanism and today
does not include them in its response at all (see below).

#### `event: final_assessment`

Emitted once, after `generate_final_assessment` completes. Payload is a
`FinalAssessment` (`app/ai/schemas.py`):

```json
{
  "ioc_value": "8.8.8.8",
  "ioc_type": "ipv4",
  "executive_summary": "...",
  "technical_summary": "...",
  "threat_assessment": "...",
  "supporting_evidence": ["..."],
  "agreeing_providers": ["virustotal", "abuseipdb"],
  "disagreeing_providers": [],
  "relationships_summary": "...",
  "mitre_mappings": [
    { "technique_id": "T1071", "technique_name": "Application Layer Protocol", "tactic": "command-and-control", "kill_chain_stage": null, "rationale": "..." }
  ],
  "risk": {
    "overall_risk_score": 5.0,
    "confidence_score": 90.0,
    "severity": "low",
    "reputation": "clean",
    "malicious_probability": 2.0,
    "analyst_confidence": "high"
  },
  "detection_rules": [
    { "format": "sigma", "title": "...", "rule": "..." }
  ],
  "recommended_actions": ["..."],
  "investigation_priorities": ["..."],
  "incident_response_recommendations": ["..."],
  "final_verdict": "benign",
  "verdict_rationale": "..."
}
```

`final_verdict` is one of: `highly_malicious`, `malicious`, `suspicious`,
`unknown`, `likely_benign`, `benign`, `scanner`, `tor_exit_node`, `vpn`,
`cdn`, `cloud_infrastructure`, `dormant_infrastructure` (`Verdict` enum,
`app/models/lookup.py`).

#### `event: done`

Emitted once, terminating the stream successfully.

```json
{ "lookup_id": "<uuid>" }
```

#### `event: error`

Emitted instead of `final_assessment`/`done` if any exception occurs after
streaming has started (the `IOCLookup` row is marked `failed`).

```json
{ "message": "<exception string>" }
```

### `GET /api/v1/lookup/{lookup_id}`

Fetch a previously completed (or in-progress) lookup by ID. Requires
`lookup:read`.

```json
{
  "id": "<uuid>",
  "ioc_value": "8.8.8.8",
  "ioc_type": "ipv4",
  "status": "completed",
  "final_verdict": "benign",
  "risk_score": 5.0,
  "confidence_score": 90.0,
  "final_assessment": { "...": "full FinalAssessment object, or null" },
  "provider_results": [
    {
      "provider_id": "virustotal",
      "provider_name": "VirusTotal",
      "category": "threat_intel",
      "status": "ok",
      "data": { "...": "..." },
      "source_url": "...",
      "error_message": null,
      "latency_ms": 842
    }
  ],
  "ai_summaries": [ { "...": "one ProviderSummary dict per summarized provider" } ],
  "created_at": "2026-08-07T12:00:00+00:00"
}
```

Notes on differences from the live SSE stream: this response does **not**
include correlation nodes/edges, and each `provider_results` row omits a few
fields present on the SSE `provider_result` event (`ioc_value`, `ioc_type`,
`fetched_at`, `from_cache`). `404` if the lookup doesn't exist.

### `GET /api/v1/lookup`

List recent lookups (most recent first). Requires `lookup:read`.

Query params: `limit` (int, default `50`).

```json
[
  {
    "id": "<uuid>",
    "ioc_value": "8.8.8.8",
    "ioc_type": "ipv4",
    "status": "completed",
    "final_verdict": "benign",
    "risk_score": 5.0,
    "confidence_score": 90.0,
    "created_at": "2026-08-07T12:00:00+00:00"
  }
]
```

## Providers

Base path: `/api/v1/providers` (`app/api/routes/providers.py`).

### `GET /api/v1/providers/health`

Requires `lookup:read`. Returns the registration/configuration status of
every provider plugin (`app/providers/registry.py`, `get_provider_health`):

```json
[
  {
    "provider_id": "virustotal",
    "provider_name": "VirusTotal",
    "category": "threat_intel",
    "configured": true,
    "requires_key": true,
    "supported_types": ["domain", "ipv4", "ipv6", "md5", "sha1", "sha256", "sha512", "url"]
  }
]
```

`configured: false` on a provider that `requires_key` means its API key is
missing from `.env` — see `docs/INSTALL.md#troubleshooting`.

## Misc

- `GET /health` (unversioned, no auth) — liveness probe:
  `{"status": "ok", "service": "HORIZON GRID"}`.
- `GET /metrics` (unversioned, no auth) — Prometheus metrics
  (`prometheus_fastapi_instrumentator`).
- `GET /docs` — Swagger UI (auto-generated OpenAPI docs for every route's
  exact request/response JSON Schema).
